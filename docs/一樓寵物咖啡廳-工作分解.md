## 零、認養規則

### 怎麼認養

1. 從本文件挑一個**依賴已滿足**的項目（見 §1 依賴圖）
2. 從 `coordination/templates/task.md` 複製一張 lease 到 `coordination/tasks/`，檔名用項目 ID，例如 `cafe-03-map-grid.md`
3. lease 的「允許修改／禁止修改」**直接抄本文件該項目的清單**，不要自己重寫
4. 完成後刪除 lease

### 兩個 Agent 的工作方式不同，這會影響認養

| | Claude Code | Codex |
|---|---|---|
| 慣用作法 | 開 feature branch，完成後由中控合併 | **直接在 `main` 上提交並推送** |
| 共用 checkout | 是（`C:\Users\User\claude_try\rent_house`） | 是（同一個） |

🔴 **因為共用同一個工作樹，同時只能有一方持有未提交的變更。**
所以認養時的鐵則是：

- **開工前先 `git status --short`**。若有不屬於你的 dirty 檔案，**不要動手**，先確認對方是否在進行中
- **一次只認養一項**，做完提交（或合併）再認養下一項
- 兩個 Agent 可以同時認養**檔案不重疊**的項目，但要錯開提交時機

### 依賴滿足的判定

每個項目有「驗收錨點」——一行可 grep 的指令。**要判斷前置項目是否完成，跑它的錨點即可**，不必問人。
這沿用 `工作日誌.md` 第四、五節既有的驗收錨點制，包含它的三條規則：

1. 完成時若實際符號與錨點不符，**改狀態的同時要把錨點改寫成真實符號**
2. 「函式體內」這類限定不能用單行 `rg`，要用兩段式
3. 已完成項目的內文若含「尚未／留待」，必須另開一條

## 二、貫穿全程的規則（每一項都適用）

寫進每一張 lease 的「禁止修改」：

| 禁止 | 原因 |
|---|---|
| 🔴 `src/sim/comfort.ts` 的 `COMMUNAL_AREA_IDS` 加入任何 cafe region | `COMMUNAL_NEUTRAL = 35.28233009708738` 立刻失效，全樓租客基準線位移，快照全紅 |
| 🔴 `INITIAL_PLACEMENTS`（`map.ts:150`）**中段插入** | `resolveTarget`（`routine.ts:176`）取陣列第一個符合的，插入會讓全樓租客的沙發/電視/廚房目標靜默改道。**只能 append** |
| 🔴 `map.ts` rows 0–32 的任何既有矩形 | 現有三樓一格都不能動，這是零漂移的第一道防線 |
| 🔴 `scripts/balance-snapshot.json` | 除非該項目**刻意**改平衡且經中控核可，否則紅燈代表實作有誤 |
| 🔴 `src/pixel/parts.ts` 的 `SKIN_TONES` / `ALL_HAIR_STYLES` / `ALL_ACCESSORIES` | 順序與長度被 `randomAppearance()` 的 `pick()` 消耗，動了會位移 seeded 序列 |
| 新增 `Math.random()` 呼叫 | 內容選擇一律用確定性雜湊（抄 `outing.ts:75` 的 `outingIndex`） |

**每一項的收工檢查**：`npm test`、`npm run build`、`npm run typecheck`、`npx tsx scripts/balance-test.ts`（**不得 `--update`**）。
程式與 `工作日誌.md` 同一個 commit（專案硬規則）；日誌加在檔尾「新紀錄追加點」以下並同步檔頭索引。
